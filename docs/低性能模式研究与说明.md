# 低性能模式研究与说明

日期：2026-09-25

## 模式行为

针对低性能手机在模型初始化期间刷新，提供一个“低性能模式”开关，默认关闭，设置保存在当前浏览器。根据开启时刷新、关闭后正常的真机反馈，模式保留“先计算完成，再播放动效”和省电画质，撤下实验性的精简初始化设置。

| 项目 | 关闭（默认） | 开启 |
| --- | --- | --- |
| 计算流程 | 计算期间可播放动效 | 先计算并保存记忆文件，再播放动效 |
| 初始化配置 | 标准配置：图优化 all、CPU 内存池开启 | 标准配置：图优化 all、CPU 内存池开启 |
| 舞台画质 | 恢复此前用户选择 | 自动切换为省电，并暂时锁定画质选择 |
| 模型文件与输入尺寸 | Lite 模型、256×256 | 相同 |

关闭开关会恢复打开前的画质。低性能模式不会重新下载模型，也不会改变生成模型文件的格式。

模式只用于手机 Lite / WASM CPU 生成路径，包括被判定为 CPU 设备的桌面浏览器；桌面完整模型 WebGPU 路径不受影响。

## 配置依据与限制

当前网站使用 ONNX Runtime Web 1.24.2。低性能模式与常规模式使用相同的标准模型初始化参数；低性能模式只改变生成与播放的先后顺序及舞台画质。WASM 仍使用单线程和顺序执行；权重预打包在原标准配置中已经关闭。

- 之前的实验配置会关闭图优化和 CPU 内存池，但这不等于减少峰值内存；图优化可能减少冗余计算并融合算子。用户反馈开启模式时在初始化阶段刷新、关闭后不刷新，因此已从低性能模式中撤下这组未经真机验证的参数。
- 该反馈说明实验配置与刷新高度相关，但仅凭页面重新加载不能证明具体由哪个底层分配触发。iOS 也可能在进程内存压力下直接终止网页，来不及显示脚本错误。
- Lite 权重仍约 800 MB，初始化时仍需整体载入运行环境；本开关没有量化、裁剪或流式读取模型，也没有更改固定 256×256 输入。
- 省电画质降低舞台渲染开销；它不降低模型初始化的权重大小。
- 浏览器进程被 iOS 终止时，页面可能来不及显示错误。现有模拟结果不能证明完整模型在 iPhone 12/14 上稳定运行。
- 低性能模式沿用标准初始化，不会在失败后自动重复创建第二个模型会话。串行流程能减少生成阶段与舞台动画同时运行的开销，但不能保证设备可用内存一定足够。

## 使用方法

手机打开“＋ 新建记忆”，打开“低性能模式”开关，再选择照片。开启后使用标准模型初始化、先生成并保存记忆文件，再播放动效；舞台画质切换为省电。关闭后恢复常规并行制作和打开开关前的画质。

## 既有验证范围

此前精简初始化的选项测试使用了小型外部权重 ONNX 模型，并在 Edge 中模拟 Worker 回复；它们只验证配置传递和基本界面控制，不代表完整模型在手机上的稳定性。本次修正未在 iPhone 上实测，仍需真机确认刷新问题是否消失。
