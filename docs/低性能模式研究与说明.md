# 低性能模式研究与说明

日期：2026-09-25

## 模式行为

针对低性能手机在模型初始化期间刷新，将此前的“精简初始化”和“先计算完成，再播放动效”合并为一个“低性能模式”开关，默认关闭，设置保存在当前浏览器。

| 项目 | 关闭（默认） | 开启 |
| --- | --- | --- |
| 计算流程 | 计算期间可播放动效 | 先计算并保存记忆文件，再播放动效 |
| 初始化配置 | 标准配置：图优化 all、CPU 内存池开启 | 实验性精简：图优化 disabled、CPU 内存池关闭 |
| 舞台画质 | 恢复此前用户选择 | 自动切换为省电，并暂时锁定画质选择 |
| 模型文件与输入尺寸 | Lite 模型、256×256 | 相同 |

关闭开关会恢复打开前的画质。低性能模式不会重新下载模型，也不会改变生成模型文件的格式。

模式只用于手机 Lite / WASM CPU 生成路径，包括被判定为 CPU 设备的桌面浏览器；桌面完整模型 WebGPU 路径不受影响。

## 配置依据与限制

当前网站使用 ONNX Runtime Web 1.24.2。WASM 接口会接收计算图优化级别和 CPU 内存池设置。低性能模式开启时，保留顺序执行、单线程和推理内存布局复用；权重预打包在原标准配置中已经关闭。

- “精简初始化”不等于已经证明更省内存。关闭图优化可能失去算子融合，使计算变慢、占用更多内存，或暴露模型算子兼容问题。
- Lite 权重仍约 800 MB，初始化时仍需整体载入运行环境；本开关没有量化、裁剪或流式读取模型，也没有更改固定 256×256 输入。
- 关闭 CPU 内存池不保证 WebAssembly 已增长的内存立即归还给系统。
- 省电画质降低舞台渲染开销；它不降低模型初始化的权重大小。
- 浏览器进程被 iOS 终止时，页面可能来不及显示错误。现有模拟结果不能证明完整模型在 iPhone 12/14 上稳定运行。
- 开关默认关闭，不自动回退或重复初始化。若初始化错误，提示关闭低性能模式后手动重试。

## 使用方法

手机打开“＋ 新建记忆”，打开“低性能模式”开关，再选择照片。开启后页面使用省电画质，待记忆文件生成并保存后再播放动效。关闭后恢复常规并行制作、标准初始化和打开开关前的画质。

## 既有验证范围

此前精简初始化的选项测试使用了小型外部权重 ONNX 模型，并在 Edge 中模拟 Worker 回复；它们只验证配置传递和基本界面控制，不代表这次融合开关已完成真机验收。本次合并未执行测试，也未在 iPhone 上实测。
