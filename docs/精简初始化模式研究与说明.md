# 精简初始化模式研究与说明

日期：2026-09-25

## 目标与结论

针对 iPhone 在“CPU 初始化”阶段刷新，提供一个可开关、可恢复原配置的实验方案。开关名称为“精简初始化（实验）”，默认关闭，记住当前浏览器中的选择，在下一次制作开始时读取。与“先计算完成，再播放动效”独立。

适用于 Lite 模型的 WASM CPU 路径。桌面完整模型的 WebGPU 路径不使用此配置。

## 已确认的实现依据

当前网站使用 ONNX Runtime Web 1.24.2。检查了本地运行库的 JavaScript 参数转换，以及同版本官方 WASM 接口：计算图优化级别、CPU 内存池选项确实传入底层运行库，不是仅修改提示文案。

| 项目 | 开关关闭：标准 | 开关开启：精简 |
| --- | --- | --- |
| 初始化时计算图优化 | all | disabled |
| CPU 内存池 | 开启 | 关闭 |
| 推理内存布局复用 | 开启 | 开启 |
| 计算方式 | 单线程、顺序 | 单线程、顺序 |
| 权重预打包 | 已关闭 | 保持关闭 |
| 模型文件与输入尺寸 | 原 Lite 模型、256×256 | 相同 |

关闭计算图优化的目标是避开初始化阶段额外的常量计算、节点融合和布局转换。关闭 CPU 内存池是实验性地改变分配与保留策略。保留推理阶段的内存布局复用，没有把所有名字含“内存”的优化一律关闭。

## 实际限制

- 精简不等于已经证明更省内存。关闭图优化可能失去有用的融合，使后续计算更慢、占用更多内存，或暴露完整模型的算子兼容问题。
- 约 800 MB 权重仍会由当前运行库完整读入。此次改动没有实现按层读取权重，也没有缩小模型。
- 关闭 CPU 内存池不保证 WebAssembly 已增长的内存会立即归还给操作系统。
- 原配置已禁用权重预打包，不能把它描述成本次新增收益。
- 官方“直接使用 ORT 模型字节”的选项适用于 ORT 格式。当前是 ONNX 加外部权重，未把该选项当作现成的免复制解决方案。
- 默认关闭；不做失败后的自动切换和重复初始化。初始化报错时提示用户关闭开关后手动重试。
- 浏览器进程被系统终止时，页面可能来不及显示错误；目前没有 iPhone 崩溃日志或真机峰值内存数据。

## 检查结果

命令：`node --test tests/mobile-initialization.cjs`

三项检查通过：

1. 关闭恢复原参数，开启不会修改标准配置对象。
2. 生成任务正确传递所选配置、释放会话；失败不自动重试，后续仍能使用标准配置。
3. 使用仓库自带 WASM 运行库和真实 ONNX 外部权重测试模型，按关闭、开启、再关闭初始化并推理，输出均为 `[11, 22, 33]`。

第三项使用的是小型测试模型。它只证明当前运行库接受并执行这些配置，不能代表完整 Lite 模型兼容性、iPhone 稳定性或省内存比例。完整模型与 iPhone 12 仍需实测。

另在本机 Edge 无头浏览器中以 390×844 页面尺寸检查了真实界面：默认关闭；开启后刷新仍开启；生成任务收到 `true`；关闭后下一次任务收到 `false`；再次刷新仍关闭。该界面检查模拟了 Worker 的模型就绪和错误回复，没有执行完整模型，也不是 iPhone 真机测试。

## 使用

手机打开“＋ 新建记忆”，在“制作顺序”下面打开“精简初始化（实验）”，然后选择照片。生成进度会明确显示“精简初始化 CPU 模型”或“标准初始化 CPU 模型”。开关不触发重新下载模型，已有模型缓存继续使用。
